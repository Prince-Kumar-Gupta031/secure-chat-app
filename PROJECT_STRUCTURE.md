## Module Responsibilities

### Backend

| File | Responsibility |
|---|---|
| `server.py` | FastAPI app, all REST routes (`/api/*`), Socket.IO server (events `send_message`, `typing`, `mark_delivered`, `new_message`, `message_status`, `messages_read`, `presence`), startup seeds Super Admin and creates indexes. |
| `models.py` | Pydantic input/output schemas: `UserRegister`, `UserLogin`, `MessageCreate`, `Chat`, `Message`, etc. Helpers `now_iso()` / `new_id()`. |
| `auth.py` | Password hashing/verification (bcrypt), JWT encode/decode, FastAPI dependencies `get_current_user_id`, `require_admin`. |

### Frontend

| Folder/File | Responsibility |
|---|---|
| `contexts/AuthContext` | Owns the user object + token; auto-rehydrates from `localStorage`. |
| `contexts/SocketContext` | Maintains a single Socket.IO connection per session; exposes `sendMessage`, `sendTyping`, `markDelivered`, presence map, and a typed `on()` listener API. |
| `contexts/ThemeContext` | Persists dark/light preference, toggles `class="dark"` on `<html>`. |
| `pages/ChatPage` | WhatsApp-style 2-pane chat. Live messages, ticks, typing, presence. |
| `pages/DirectoryPage` | Search + grid of approved employees; click → opens chat. |
| `pages/AdminPage` | Tabs: Dashboard / Approvals / Users / Audit logs. Auto-refresh every 15s. |

## Data Flow (Send Message)

```
ChatPage
   │
   ├── sendMessage({peer_id, text})
   ▼
SocketContext.sendMessage  ──emit "send_message"──▶  Server
                                                       │
                                            persists in Mongo, sets
                                            status = delivered if peer online
                                                       │
   ◀──"new_message" to sender sids──┬──────────────────┤
                                    │                  │
   ◀──"new_message" to peer sids────┘                  │
                                                       │
ChatPage `on("message")` updates local list ◀──────────┘
```

## State / Storage

- **Authentication:** JWT in `localStorage` (`drdo_token`). Re-fetched into `AuthContext` on every reload.
- **Presence:** in-memory map on the backend (`ONLINE: dict[user_id, set[sid]]`); broadcast to all clients via `presence` event.
- **Messages:** persistent in Mongo collection `messages`; loaded on chat open via REST + appended live via socket.
- **Files:** stored on disk in `UPLOAD_DIR` under randomized UUID names; metadata in `files` collection.

## Adding a New Feature (Phase-2 example: Star Message)

1. Add `starred_by: List[str]` to `Message` model.
2. New REST endpoint `POST /api/messages/{id}/star` in `server.py`.
3. UI: add a star icon button to `MessageBubble`, optimistic update.
4. Add a "Starred" tab on `ChatPage` sidebar that queries `/api/messages?starred=true`.
